# Design: voucher-topup-and-remove-export

## Approach

Two independent slices:

1. **Voucher UI (web only).** Introduce a static voucher catalog module and rewrite the
   Mezon section of the Add Funds card as a voucher grid. Claim mechanics stay identical —
   the grid only changes what the user sees as the transfer amount before pasting a hash.
2. **Export removal (Go + web).** Delete the monthly report feature through every layer and
   let the Go module drop `gofpdf`.

## Interfaces

- `VoucherDenomination { amount: number; image: string; key: string }` and
  `VOUCHER_DENOMINATIONS: VoucherDenomination[]` — the single source of truth for the grid.
- `VoucherSectionProps` keeps the shape of `MezonTopupSectionProps`
  (`treasuryAddress`, `explorerUrl?`, `onClaim`, `claiming`) so `RechargeFormCard` and
  `index.tsx` wiring stay compatible; only the component internals change.
- Go API surface: no endpoint is added or changed; one admin route is removed.

## Database

No migration. The `top_ups` table and `CompleteMezonTopUp` flow are untouched; the only
deleted query (`GetMezonTopUpReport`) was read-only and used standard GORM `Table/Select/
Joins`, so removal has no dialect implications.

## Relay Adapter

Not applicable — no relay surface is touched.

## Billing

Unchanged credit chain: claim → indexer verify (`service.GetMezonTransaction`) →
`service.MezonRawValueToDong` → `mezonDongToQuota` (group ratio + `common.QuotaRoundChecked`
saturation) → `model.CompleteMezonTopUp` (unique `trade_no`, quota-limit guard). Voucher
selection never enters this chain.

## Dependencies

- Independent of other in-flight changes; builds on the merged upstream `main`.
- Depends only on assets already present under `web/public/vouchers/`.
- Nothing else depends on the deleted report symbols (verified: single callsite each).
